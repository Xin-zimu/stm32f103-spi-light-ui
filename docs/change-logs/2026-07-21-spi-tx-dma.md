# SPI TX DMA

日期：2026-07-21

## 修改目标

为 ST7789 彩屏的 SPI2 发送路径加入 TX DMA，减少逐字节等待 SPI 发送寄存器带来的 CPU 占用。

## 修改前行为

ST7789 驱动通过 `ST7789_WriteStreamByte` 逐字节写 SPI2 数据寄存器。清屏、矩形填充、首帧显示和差分帧更新都会在像素循环中不断等待 TXE 标志，CPU 参与每个发送字节。

## 修改后行为

SPI2 初始化时同步配置 DMA1 Channel5，并打开 SPI2 TX DMA 请求。ST7789 驱动新增一行 RGB565 DMA 缓冲区，清屏、矩形填充、4 位索引首帧和差分帧变化段都先构建一行或一段像素数据，再通过 DMA1 Channel5 发送到 SPI2。DMA 发送函数仍保持同步返回，返回前会等待 DMA TC5 和 SPI2 BSY 清零。

## 逻辑变化范围

- `ST7789_SPI_Init` 增加 DMA1 时钟、DMA1 Channel5 配置和 SPI2 TX DMA 请求使能。
- 新增 `ST7789_WriteBufferDMA`，使用 DMA1 Channel5 向 SPI2 发送连续字节缓冲。
- 新增 `ST7789_FillColorLine`，为单色清屏和矩形填充构建一行 RGB565 DMA 数据。
- 新增 `ST7789_BuildIndexed4Line`，把 4 位索引像素解码为 RGB565 DMA 行缓冲。
- `ST7789_Clear`、`ST7789_FillRect`、`ST7789_ShowIndexed4Image` 和 `ST7789_ApplyIndexed4Delta` 从逐字节 SPI 发送改为按行或按段 DMA 发送。

## 接口与兼容性

对外头文件接口不变。SPI2 TX DMA 使用 STM32F103 固定映射的 DMA1 Channel5；USART1 TX DMA 仍使用 DMA1 Channel4，二者不冲突。DMA 发送保持同步阻塞语义，因此现有上层调用顺序和屏幕命令/数据 DC 时序保持兼容。
