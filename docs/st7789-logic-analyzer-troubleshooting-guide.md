# ST7789 与逻辑分析仪排障学习指南

## 1. 文档目标

本文以 STM32F103C8T6 驱动七针无 CS 的 ST7789 彩屏为实例，说明如何从
“背光亮但无图像”逐步定位到 SPI 模式和屏幕分辨率问题。

重点不是记住某一块屏幕的参数，而是掌握一套可以重复使用的排障方法：

1. 确认实际编译和烧录的代码。
2. 确认引脚、电源、复位和背光。
3. 用逻辑分析仪检查电平、时序、字节和协议语义。
4. 用纯色测试隔离图片、动画和文件格式问题。
5. 根据实屏现象判断分辨率、偏移、颜色顺序和初始化参数。

## 2. 本次硬件与最终配置

### 2.1 接线

| ST7789 | STM32F103C8T6 | 功能 |
| --- | --- | --- |
| GND | GND | 电源地和逻辑分析仪公共参考地 |
| VCC | 3.3V | 模块电源 |
| SCL | PB13 | SPI2 SCK |
| SDA | PB15 | SPI2 MOSI |
| RES | PB10 | 硬件复位 |
| DC | PB14 | 命令或数据选择 |
| BLK | PB12 | 背光控制，高电平点亮 |

该模块没有 MISO 和外部 CS。屏幕上的 `SCL`、`SDA` 是 SPI 信号，不是 I2C。

### 2.2 最终实测配置

```c
#define ST7789_WIDTH       240U
#define ST7789_HEIGHT      320U
#define ST7789_X_OFFSET    0U
#define ST7789_Y_OFFSET    0U
#define ST7789_SPI_MODE    3U
```

SPI2 约为 4.5 MHz，8 位数据，MSB First，RGB565，单向发送。

以上参数只代表本次实物模块。其他同名 ST7789 模块可能使用不同分辨率、偏移或
SPI 模式，不能直接照搬。

## 3. 本次问题是怎样逐层暴露的

### 3.1 驱动对象不一致

工程最初面向 SSD1306 128x64 单色 OLED。SSD1306 与 ST7789 的初始化命令、
地址方式和像素格式完全不同。仅改变接线不能让 ST7789 识别 SSD1306 数据。

处理方法是先建立最小 ST7789 驱动，不播放 GIF，不加载图片，只循环显示纯色。

### 3.2 工程中存在多套历史代码

目录曾同时保留：

- SSD1306 OLED 驱动；
- ST7789 动画驱动；
- GPIO 软件 SPI；
- SPI2 硬件 SPI；
- GPIOA 和 GPIOB 两套引脚；
- 多个实验入口。

因此必须检查 Keil 工程实际参与编译的文件，不能根据“目录里存在某文件”判断固件
行为。最终确认实际入口为 `User/main.c`，实际显示驱动为
`User/bsp_st7789.c`。

### 3.3 Mode 0 有数据但屏幕不显示

逻辑分析仪确认 STM32 在 Mode 0 下确实产生了时钟和 MOSI 数据，但屏幕没有有效
显示。将 SPI 改为 Mode 3 并重新编译烧录后，屏幕开始显示纯色。

这说明“主控发出了数据”不等于“从设备按正确边沿接收了数据”。

### 3.4 四分之一高度花屏

屏幕点亮后出现一整条横向花屏，约占高度四分之一。旧配置为：

```c
#define ST7789_HEIGHT      240U
#define ST7789_Y_OFFSET    80U
```

它只向第 80 至 319 行写入 240 行像素。实物却是 240x320 全屏，因此其余 80 行
没有刷新，保留了随机显存内容。

改为 320 行、Y 偏移 0 后，每次写满 76800 个像素，花屏消失。

## 4. 逻辑分析仪到底能证明什么

逻辑分析仪不只是检查“有没有波形”。它可以分四层分析。

### 4.1 第一层：引脚是否活动

检查：

- SCK 是否产生时钟；
- MOSI 是否变化；
- DC 是否切换；
- RES 是否出现低电平复位脉冲；
- BLK 是否在初始化完成后变高。

这一层只能证明引脚和程序有活动，不能证明协议内容正确。

### 4.2 第二层：电气时序是否合理

可以测量：

- SPI 时钟频率；
- 时钟空闲电平；
- 数据在时钟边沿附近是否稳定；
- 复位低电平持续时间；
- 命令与数据之间的 DC 切换关系。

普通逻辑分析仪把电压简化为 0 和 1，无法可靠观察过冲、振铃、缓慢上升沿等模拟
问题。检查这些问题需要示波器。

### 4.3 第三层：SPI 字节是否正确

在 PulseView 中加入 SPI 解码器后，应设置：

```text
CLK      CH1
MOSI     CH2
MISO     未使用
CS       未使用
Mode     3
CPOL     1
CPHA     1
Bit order MSB First
Word size 8 bit
```

若解码器持续输出稳定的字节，而不是随机跳变，说明基本时钟、位序和采样边沿大致
匹配。

### 4.4 第四层：字节是否符合 ST7789 协议

仅看到十六进制字节还不够，还要结合 DC 判断含义：

- `DC=0`：命令；
- `DC=1`：命令参数或像素数据。

全屏刷新应包含：

```text
2A  00 00 00 EF    列地址 0 至 239
2B  00 00 01 3F    行地址 0 至 319
2C                 开始写显存
```

其中：

```text
0x00EF = 239
0x013F = 319
```

这组数据能直接证明固件正在设置 240x320 地址窗口，而不仅是“SPI 有输出”。

## 5. 如何验证纯色数据

ST7789 当前使用 RGB565，每个像素发送两个字节：

| 颜色 | RGB565 | 线上字节 |
| --- | --- | --- |
| 红 | `0xF800` | `F8 00` |
| 绿 | `0x07E0` | `07 E0` |
| 蓝 | `0x001F` | `00 1F` |
| 白 | `0xFFFF` | `FF FF` |
| 黑 | `0x0000` | `00 00` |

本次抓包实际观察到了这五组数据。由此可以确认：

- 主程序确实在执行五色循环；
- RGB565 高字节先发送；
- MOSI 数据内容正确；
- SPI 时钟约为 4.5 MHz；
- DC 在地址命令和像素数据之间正确切换。

240x320 全屏一次需要发送：

```text
240 x 320 x 2 = 153600 字节
```

如果只发送 240x240，则像素数据只有：

```text
240 x 240 x 2 = 115200 字节
```

二者相差 38400 字节，也就是缺少 80 行。

## 6. 逻辑分析仪不能单独证明什么

本模块没有 MISO，因此 STM32 无法读取屏幕应答。即使逻辑分析仪确认以下内容全部
正确：

- SCK 正常；
- MOSI 字节正确；
- DC、RES、BLK 正常；
- 地址窗口和颜色数据正确；

仍不能单独证明 ST7789 内部已经接受并执行命令。以下问题仍可能存在：

- 探头测的是 MCU 引脚，但杜邦线另一端断路；
- 模块控制器型号与标注不一致；
- SPI 边沿对模块不合适；
- 模块供电或电平转换异常；
- 初始化参数不适合该面板；
- 屏幕本体损坏。

因此最可靠的方法是把探头接在屏幕排针处，并结合实屏显示结果判断。

## 7. 为什么 ST7789 会遇到 SPI Mode 问题

SPI 模式由 CPOL 和 CPHA 组成：

| 模式 | CPOL | CPHA | 时钟空闲 | 常用采样边沿 |
| --- | --- | --- | --- | --- |
| Mode 0 | 0 | 0 | 低 | 上升沿 |
| Mode 1 | 0 | 1 | 低 | 下降沿 |
| Mode 2 | 1 | 0 | 高 | 下降沿 |
| Mode 3 | 1 | 1 | 高 | 上升沿 |

ST7789 资料描述串行数据在 SCL 上升沿进入。Mode 0 和 Mode 3 都可以形成上升沿
采样，但它们的空闲电平和第一个有效边沿不同。

实际模块还会受到以下因素影响：

- 模块是否引出了 CS；
- CS 是否在模块内部固定为有效状态；
- 数据是否在第一个时钟边沿前已经稳定；
- MCU 外设对 CPHA 的具体定义；
- 杜邦线长度和信号质量；
- 模块版本或兼容控制器；
- 厂商示例代码采用的历史配置。

所以网上会同时出现“ST7789 应使用 Mode 3”和“某块 ST7789 必须使用 Mode 0”
的案例。正确做法不是争论统一答案，而是：

1. 查具体模块资料；
2. 从较低 SPI 频率开始；
3. 用逻辑分析仪检查空闲电平和数据边沿；
4. 分别测试 Mode 0 与 Mode 3；
5. 记录实物验证结果。

本次模块最终确认使用 Mode 3。

## 8. PulseView 的实用操作流程

### 8.1 接线

```text
CH1 -> PB13 / SCK
CH2 -> PB15 / MOSI
CH3 -> PB14 / DC
CH4 -> PB10 / RES
CH5 -> PB12 / BLK
GND -> 开发板 GND
```

分析仪接口上单独标记的 `CLK` 是外部采样时钟输入，不是必须连接的 SPI SCK
通道。本次把 SPI SCK 接普通数字通道 CH1。

### 8.2 采样率

SPI 时钟约 4.5 MHz。最低应取时钟的 4 至 5 倍，建议：

```text
24 MHz：可以使用
48 MHz：边沿定位和解码更稳妥
```

采样率过低可能看得到跳变，却无法可靠恢复每一位。

### 8.3 触发

常用触发方式：

- 抓运行中刷屏：SCK 上升沿触发；
- 抓完整初始化：RES 下降沿触发，然后按开发板复位键；
- 无法确定通道时：先无触发采一段，观察哪些通道变化。

程序每种颜色保持 1 秒。无触发短采样可能恰好落在等待阶段，看到所有通道不变。
这不代表没有 SPI，需要使用时钟触发或延长采样时间。

### 8.4 先看波形，再开解码

推荐顺序：

1. 确认 SCK 是否活动；
2. 测量频率和空闲电平；
3. 确认 MOSI 在时钟边沿附近变化；
4. 确认 DC 能区分命令和数据；
5. 再添加 SPI 解码器；
6. 对照 ST7789 命令表检查 `2A`、`2B`、`2C`；
7. 对照 RGB565 检查像素字节。

如果直接依赖解码器，错误的 Mode、位序或通道映射也可能产生看似正常的随机字节。

## 10. 网上常见 ST7789 故障分类

### 10.1 背光亮但没有图像

背光通常是独立 LED 电路。背光亮只能证明 VCC、GND 和 BLK 基本正常，不能证明
控制器已经初始化。

重点检查：

- RES 是否有低电平脉冲；
- DC 是否接反；
- SCK 与 SDA 是否误按 I2C 接法；
- SPI Mode；
- CS 是否需要连接；
- 初始化后是否发送 `SLPOUT` 和 `DISPON`。

### 10.2 只有部分区域显示或出现横条花屏

重点检查：

- 实际面板是 240x240 还是 240x320；
- `2A`、`2B` 的起止地址；
- X/Y 偏移；
- 实际发送的像素数量；
- 屏幕扫描方向。

### 10.3 红蓝互换

重点检查 MADCTL 的 RGB/BGR 位，而不是交换每个像素的高低字节。

### 10.4 画面旋转、镜像或坐标错乱

检查 MADCTL 的行列交换、X 镜像和 Y 镜像位，并同步调整宽高和地址窗口。

### 10.5 高速正常性差

降低 SPI 频率，缩短杜邦线，保证共地，并使用示波器检查时钟和数据边沿。

### 10.6 同样型号却要不同参数

“ST7789”通常只说明控制器系列，不代表：

- 面板一定是同一分辨率；
- 可视区域一定从显存第 0 行开始；
- 模块一定引出 CS；
- 模块一定使用相同初始化参数；
- PCB 上一定没有电平转换或其他逻辑。

模块照片、卖家标题和示例程序只能作为线索，最终应以数据手册、逻辑分析仪和实屏
验证共同确定。

## 11. 推荐的标准排障顺序

### 阶段一：确认软件对象

1. 检查 Keil 实际编译的入口和驱动。
2. Rebuild 并确认零错误。
3. 确认烧录的是最新生成的 AXF/HEX。
4. 暂停 GIF、字体和动画，只保留纯色。

### 阶段二：确认基本硬件

1. 测量 3.3V 和 GND。
2. 检查逻辑分析仪与开发板共地。
3. 确认 BLK。
4. 确认 RES 脉冲。
5. 确认 SCK、MOSI 和 DC 接线。

### 阶段三：确认 SPI

1. 从 1 至 5 MHz 开始。
2. 检查 SCK 频率和空闲电平。
3. 检查 MOSI 位序。
4. 尝试 Mode 0 和 Mode 3。
5. 解码初始化命令和地址窗口。

### 阶段四：确认面板参数

1. 先刷黑、红、绿、蓝、白。
2. 检查是否全屏覆盖。
3. 根据横条花屏判断高度和偏移。
4. 根据颜色判断 RGB/BGR。
5. 根据方向判断 MADCTL。

### 阶段五：恢复应用功能

只有纯色测试完全稳定后，才依次恢复：

1. 单张测试图片；
2. 两帧切换；
3. 非阻塞动画；
4. GIF 转换数据。

这样每一步只引入一个新变量，出现问题时容易定位。

## 13. 最重要的经验

1. 有波形不等于协议正确。
2. 字节能解码不等于屏幕一定接收成功。
3. 背光亮不等于控制器正常工作。
4. ST7789 芯片型号不等于具体模块参数。
5. 纯色测试是显示驱动最有效的第一阶段验收方法。
6. 逻辑分析仪、数据手册和实屏现象必须结合使用。
7. 最终有效配置必须记录为具体实物的实测结论，不能只依赖网络示例。
