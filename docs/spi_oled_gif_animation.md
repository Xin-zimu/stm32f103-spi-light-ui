# ST7789 GIF 动画实现说明

## 原始素材

`小猫图.gif` 的参数为：

- 尺寸：120x120。
- 原始帧数：28。
- 原始间隔：40 ms。
- 循环时间：1120 ms。
- 带透明背景和 GIF disposal 帧处理。

Pillow 先按 GIF 规则合成每一帧，再进行颜色量化。不能直接把各帧的局部
矩形当作完整图像，否则透明区域和 disposal 处理会产生残影。

## 为什么不保存全部整帧

120x120 图像使用 RGB565 时，每帧需要 28800 字节；28 帧需要约 788 KB。
即使使用 16 色 4 位索引，每帧仍需 7200 字节，28 帧约 197 KB。

STM32F103C8 工程配置为64 KB Flash，项目已迁移到获得正式授权的
Arm Compiler 6.24，不再受旧ARMCC 5 Lite的32 KB镜像限制。固件采用：

- 保留全部28个原始帧。
- 保持原始40 ms播放间隔。
- 全部帧共用 16 色 RGB565 调色板。
- 首帧完整保存，所有相邻帧及末帧回首帧只保存变化像素。

最终首帧占7200字节，28个循环帧差共49109字节。

## 帧差格式

数据按 120 个源像素一行进行编码。每段以一个控制字节开始：

```text
bit7 = 1：跳过该段，保留 ST7789 上一帧显存
bit7 = 0：绘制该段，后面跟随打包的 4 位颜色索引
bit6..0：段长度减 1，范围为 1 到 128 个源像素
```

每个绘制段会转换为一个 ST7789 地址窗口。源像素在 X、Y 方向各重复两次，
所以 120x120 数据覆盖 240x240 屏幕。未变化段不发送像素，既减少 Flash
数据，也减少 SPI 传输时间。

播放循环回到第0帧时也使用末帧到首帧的帧差，避免循环边界出现完整刷屏停顿。

## 非阻塞的含义

TIM3每1 ms增加一次计数。主循环反复调用动画任务，未到40 ms时立即返回，
因此等待阶段不占用 CPU，可以继续加入按键、传感器或通信任务。

当前写屏分为两类：

- ST7789 初始化、命令、控制参数和地址窗口仍使用同步 SPI 字节发送。
- 清屏、矩形填充、完整帧和 GIF 差分像素流使用 SPI2 TX DMA 发送。

SPI2 TX 映射到 DMA1 Channel5。驱动准备两个 240 像素行缓冲，DMA 完成
中断释放发送状态；动画任务在 DMA 忙时立即返回，下一轮主循环继续推进
差分状态机。DMA 完成只代表最后一个字节写入 SPI2 数据寄存器，切换 DC
或设置下一个地址窗口前仍会等待 SPI2 BSY 清零，避免最后一个像素被解释
为命令或控制字节。

这仍是裸机协作式调度，不引入 RTOS，也不创建全屏帧缓冲。

## 生成与校验

生成脚本为 `Tools/generate_st7789_gif.py`。它会：

1. 检查输入尺寸。
2. 生成全局 16 色调色板。
3. 量化并编码全部28帧数据。
4. 对每个帧差执行反向解码，必须与量化帧完全一致。
5. 将输入 GIF 的 SHA-256 写入头文件，便于确认数据来源。

生成的`anim_frames.c/.h`使用代码页936、无BOM，适配Arm Compiler 6工程。

运行时的异步差分任务也会检查流边界。非零差分流必须通过跳过段和绘制段
覆盖完整 120x120 源图；如果数据提前结束、段长度越过行尾、绘制段载荷
不足，或完整图像覆盖后仍有多余字节，任务会返回错误。上层动画任务会重画
完整首帧并从第0帧重新开始，避免屏幕显存停留在不确定状态。

## 硬件通信

```text
SPI2 SCK  -> PB13
SPI2 MOSI -> PB15
RES       -> PB10
DC        -> PB14
BLK       -> PB12
SPI Mode  -> Mode 3
SPI CLK   -> 约 18 MHz
SPI2 TX DMA -> DMA1 Channel5
```
